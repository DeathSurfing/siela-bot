# Siela Bot — Runbook

## First deploy

```bash
git clone https://github.com/DeathSurfing/siela-nogseuui-seobeo-bot.git
cd siela-nogseuui-seobeo-bot

export DISCORD_TOKEN="..."
# optional:
export GUILD_ID="..."
export DISCORD_CLIENT_ID="..."
./scripts/podman-init.sh

./scripts/podman-stack.sh up -d --build
podman ps --format '{{.Names}}\t{{.Status}}'
```

The bot auto-detects the guild when it is in exactly one guild.

## Common commands

```bash
# logs
./scripts/podman-stack.sh logs -f bot
./scripts/podman-stack.sh logs -f translator

# restart one service
podman restart siela-bot
podman restart siela-translator

# health
podman healthcheck run siela-bot
podman healthcheck run siela-translator

# stop the stack (volumes are kept)
podman compose -p siela -f deploy/podman/compose.yaml down

# destroy everything, including the database
podman compose -p siela -f deploy/podman/compose.yaml down -v
```

## Updates

```bash
git pull
podman compose -p siela -f deploy/podman/compose.yaml build
podman compose -p siela -f deploy/podman/compose.yaml run --rm migrate
podman compose -p siela -f deploy/podman/compose.yaml up -d
```

## Backups

```bash
mkdir -p /var/backups/siela
podman exec siela-postgres pg_dump -U siela -Fc siela \
  | gzip > "/var/backups/siela/siela-$(date +%F).dump.gz"
```

Restore:

```bash
gunzip -c /var/backups/siela/siela-YYYY-MM-DD.dump.gz \
  | podman exec -i siela-postgres pg_restore -U siela -d siela --clean --if-exists
```

## Remote Podman Desktop

Podman Desktop can manage the server stack over SSH. The remote host needs the
rootful Podman socket (`/run/podman/podman.sock`), which is already enabled by
`podman.socket` on this host.

On the Mac:

```bash
ssh-keygen -t ed25519 -f ~/.ssh/siela_podman_ed25519
ssh-copy-id -i ~/.ssh/siela_podman_ed25519.pub root@192.168.1.3

podman system connection add siela-server \
  --identity "$HOME/.ssh/siela_podman_ed25519" \
  ssh://root@192.168.1.3/run/podman/podman.sock
```

Then enable **Podman Desktop → Settings → Preferences → Enable remote
connections** (setting key `podman.system.connections.remote`). The
connection appears as `siela-server` in the container engine picker.

This is a rootful connection: the SSH key has full control of the server.
Restrict it to the LAN in `/root/.ssh/authorized_keys` and revoke it when not
needed. Remove the connection with:

```bash
podman system connection remove siela-server
```

## Troubleshooting

- **Bot exits with `Invalid environment`**: check `deploy/podman/.env`; `DISCORD_TOKEN` is required and internal secrets are generated by `scripts/podman-init.sh`.
- **Bot is not in the guild**: invite it with `bot` + `applications.commands` and the permissions in the plan.
- **Music does not play**: check `podman exec siela-bot yt-dlp --version` and `podman exec siela-bot mpv --version`. Music uses yt-dlp + mpv, not Lavalink. Spotify links are resolved through Spotify's public oEmbed metadata and then searched on SoundCloud.
- **Translation is down**: the first Hugging Face NLLB boot downloads the model (roughly 2.4 GiB); wait for the healthcheck and check `podman logs siela-translator`. The translator is memory-hungry (4 GiB limit); keep the host at 8 GiB.
- **MCP is not running**: it is optional and off by default. Set `MCP_ENABLED=true` in `deploy/podman/.env`, then run `scripts/podman-stack.sh up -d`.
- **MCP unreachable from the host**: it is on the internal `mcp` network by default. Use `compose.mcp.yaml` plus `compose.host.yaml` for `127.0.0.1:8080`, or run the MCP client as a container on `siela_mcp`.
